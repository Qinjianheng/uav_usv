# 项目架构

## 数据链路

```text
相机/深度/激光
      -> perception/TargetObservation
      -> tracking/TargetState
      -> guidance/TrajectoryPoint[]
      -> controllers/速度或加速度指令
      -> PX4 Offboard
```

`/ground_truth/*` 只用于仿真评估。正式闭环控制应使用 `/tracking/target_state`，避免把仿真真值当作感知结果。

## 模块职责

- `perception`：检测、深度、激光测距、坐标变换与观测协方差。
- `tracking`：时间同步、EKF/IMM、目标速度估计和状态有效性。
- `guidance`：截击时间、目标轨迹预测、PN/APN及路径规划。
- `controllers`：PID、MPC和后续安全约束下的强化学习控制器。
- `mission`：INIT、TAKEOFF、FOLLOW、INTERCEPT、COMPLETE状态机。
- `common`：坐标、限幅、时间戳和通用数据结构。

所有控制器最终应实现统一接口：输入无人机状态、目标状态、参考轨迹和时间步，输出控制指令与诊断信息。

当前跟踪基线使用六状态恒速度线性卡尔曼滤波器，仅订阅 `/target/position` 位置观测，不读取目标真值速度。滤波后的 `[px, py, pz, vx, vy, vz]` 和6×6协方差发布到 `/tracking/target_state`；按配置预测时域外推的位置发布到 `/tracking/predicted_position`。路径规划器应订阅 `TargetState`，并根据自身规划时域使用状态与协方差进行预测。

现阶段滤波器与真值截击控制并行运行，用于先验证估计误差。完成验证前，现有命中判定仍使用真值，不将滤波估计混入评价链路。

当前截击阶段在每个20 Hz控制周期重新规划。规划器由相邻速度方向变化估计目标转向率，使用1–2秒短时协调转弯（CTRV）模型预测8字等曲线运动。远离目标时采用直接闭合与安全高度待机；进入有限时域可达域后，五次多项式同时满足UAV当前位置/速度/加速度以及末端目标位置/速度/加速度。规划器联合搜索末端时间和闭合速度，并沿整条候选轨迹检查水平/垂直速度、加速度、捕获半径和触海约束；每个周期执行轨迹上前视0.75秒的速度状态，相当于短执行窗口 `M<N`，避免只取五次多项式起点附近造成滚动时域停滞。只有可行轨迹才允许最终下降。起飞阶段同时执行Z轴位置控制和XY轴跟随速度控制。预测输入暂时仍来自 `/target/*` 真值话题，成功、触海和最小距离继续由实际相对状态判定；切换传感器后只应替换规划输入，不能替换评价真值。

## 观测约束与后续传感器闭环

本节的设计依据为 Gao 等（2024）《Adaptive Tracking and Perching for Quadrotor in Dynamic Scenarios》，后续引入相机、深度相机或激光雷达时必须重新对照该论文的目标状态估计、可见性约束与末端状态同步方法。

按论文式观测约束，期望观测偏航定义为 `psi_e(p,q) = atan2(q_y-p_y, q_x-p_x)`。当前控制器已经在每个周期根据UAV位置 `p` 与USV估计位置 `q` 更新该偏航，并进行 `[-pi, pi)` 连续化和偏航速率限制。该约束现在保证机头朝向目标，后续应扩展为规划代价中的观测距离、视场角和遮挡约束。

USV是非合作目标，因此不能照搬论文中的视觉标记。引入相机与激光雷达时采用以下替代链路：相机目标检测/分割提供方位与类别，激光雷达在相机视锥内关联点云并提供距离，二者经时间同步、外参和TF变换形成带协方差的 `TargetObservation`；CTRV-EKF估计状态并在数据充分时生成CTRA运动原语，数据不足时退回CV。规划器只读取融合后的 `TargetState` 及协方差，并把目标留在共同视场内；Gazebo全局真值仅用于成功判定和误差评估。

偏航约束只规定水平朝向。安装真实/仿真传感器后，还必须根据相机光轴、机体姿态和云台自由度检查俯仰观测角；若使用前视固定相机，则把俯仰/FOV同时加入轨迹可行性约束，不能仅凭偏航满足就认定目标始终可见。

### 双相机接入阶段

仿真机型采用固定前视和固定下视两台相机，对应论文实机中避免摄影云台链路延迟的安装选择。前视相机光轴沿机体前向，安装点为机体系 `(0.12, 0, 0.10)` 米；下视相机光轴由机体前向绕Y轴旋转90度指向下方，安装点为 `(0, 0, 0.06)` 米。前/下视水平FOV分别为1.74/2.0 rad，图像为640×480、20 Hz。FOV数值是当前仿真参数，不应表述为论文原始相机参数。

可见性监视器同时发布两路ROS图像与 `CameraInfo`，以红色目标球的像素数量验证视场。距离不超过2米且机体俯仰小于30度时优选下视相机，否则优选前视相机；这对应论文中依据末端姿态选取底部/前部相机的做法。当前切换只影响诊断输出 `/perception/active_camera`，不会改变控制输入。

感知闭环分三步迁移：

1. 当前：`/target/*` 真值负责控制、预测和评价，相机仅旁路验证可见性；
2. 影子验证：相机检测生成观测与估计轨迹，与真值误差并行记录，但控制仍使用真值；
3. 正式闭环：规划器改读融合后的 `TargetState`，真值仅用于误差和截击结果评价。

正式闭环还需把论文的观测距离（OD）、观测角（OA）和遮挡效应（OE）写入轨迹代价/可行性约束。当前红色像素计数只能确认目标在画面中，尚不能证明目标位于理想成像区域，也不能处理海浪、机体遮挡或无标记USV识别。

## 截击结果判定

截击从Y命令被接受时开始计时。真值相对轨迹在相邻控制周期之间连续进入半径为0.25米的三维捕获球时，判定为成功；不能只检查离散采样点。默认30秒未进入捕获球则判定失败。

结果发布到 `/simulation/impact/result`，消息类型为 `uav_usv_interfaces/InterceptResult`。结果区分 `SUCCESS`、`FAILURE` 和 `ABORTED`，失败原因包括 `TIMEOUT`、`STATE_LOST`、`OFFBOARD_LOST`、`CONSTRAINT_VIOLATION` 与 `INVALID_STATE`。

`/simulation/impact/hit` 只在真实成功时发布 `true`。CSV最终行保存真实捕获边界处的UAV和USV坐标，不得为了显示效果把两者坐标强制写成完全重合。真值只用于结果判定和评价，后续感知闭环不得读取该结果作为控制输入。

## 坐标约定

PX4本地坐标采用NED：x向北、y向东、z向下。相机输出必须先通过TF转换，禁止直接把相机光学坐标作为PX4设定值。
